# 多任务氮气（multitask-nitro）

**通用批量任务调度技能**：识别可并行任务，选择合适的执行载体，在资源、限流、依赖和副作用约束下提高成功吞吐量。

本技能负责**执行调度**，不替代任务本身的专业判断、质量验收和授权管理。

## 定位

批量任务（转写一堆视频、转码、批量下载、批量抓取、批量分析、批量调 API……）默认一条一条跑太慢；本技能判断"是否值得并发、怎么并发"，同时守住资源与副作用安全线——快，但不翻车。

## 核心机制（V0.2 十一节）

| 环节 | 规则 |
|---|---|
| 并发决策 | 五问判断（独立性/依赖/耗时收益/资源限流/共享冲突）→ 并发、串行或依赖分层；对象 ≥3 只是默认触发参考，非强制 |
| 依赖管理 | 无依赖并行；有依赖层内并行层间等待；查循环依赖与缺失输入；前置未验证成功不启动后继 |
| 执行载体 | 机械→本地进程池；AI 判断→子代理；混合分层。环境能力不足→明确降级，不假称并发 |
| 资源与限流 | 按任务类型定限制因素（CPU/网络/API 配额/显存）；读不到数据用保守默认值，不虚构检测 |
| 自适应调度 | 以成功吞吐量为目标：保守起步→无失败缓步加→限流立即降（Retry-After/指数退避）→锁定；同目标服务统一限流 |
| 失败与重试 | 重试前三类判定（确认未执行/状态不明先核对/已执行按性质补偿）；**非幂等副作用任务不得盲目自动重试** |
| 状态与断点续跑 | 四状态 PENDING/RUNNING/SUCCEEDED/FAILED；先验证输出再标成功；临时文件写完验证后再原子替换 |
| 结果验证 | 成功 ≠ 命令返回成功；按任务类型检查输出存在/完整/可读/内容质量；未验证不得归入成功 |
| 取消与停止 | 停派新任务、运行中安全收尾、保留已完成、记录未完成——停止/跳过不得写成成功 |
| 交付 | 成功/失败/跳过/**未验证**分列 + 实际并发度与耗时；无真实串行基准标估算，不伪装实测加速比 |
| 红线 | 不突破限流 / 不乱序依赖 / 不对状态不明的非幂等任务盲目重试 / 不把命令成功当结果成功 / 不虚报并发与加速 / 不把失败跳过取消未验证写成成功 |

## 与其他技能分工

| Skill | 管什么 |
|---|---|
| preflight（前置技能） | 做得**对**（任务目标、质量判断、交付验收） |
| multitask-nitro（本技能） | 做得**快**（批量执行与调度） |
| skill-reuse（技能复用调度） | 用现成**工具**（注册表、借用） |

## 能力边界（重要）

本技能是**调度规则**。实际并发能力依赖运行环境的工具、子代理接口、进程权限与本地执行条件——环境不具备并发能力时，按规则降级为串行并如实说明，不虚报并发执行。

## 安装

### Hermes

1. 下载 Release 的 `multitask-nitro-0.2.0.tgz` 并解压
2. 把 `multitask-nitro` 目录放入 Hermes 的 skills 目录（`$HERMES_HOME/skills/`）
3. 新开会话，批量任务自动触发

### DSH

- 桌面版：插件面板 → 添加插件 → 粘贴 `https://github.com/wo-yu-qiu-de-dao-ni/multitask-nitro`
- CLI：下载 Release 的 `dsh-multitask-nitro-0.2.0.tgz` → `dsh plugin --profile web add ./dsh-multitask-nitro-0.2.0.tgz`
- 注入档位：`config.level: full | mini`（cordis.patch.yml 或 profile 层覆盖）
