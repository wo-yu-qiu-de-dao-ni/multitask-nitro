# 多任务氮气（multitask-nitro）

**执行层加速器**：把串行批量任务自动转成受控并发，并按本机资源 / API 限流 / 目标网络自适应并发度，找到"又快又稳"的甜蜜点。

## 定位

批量任务（转写一堆视频、转码、批量下载、批量抓取、批量分析、批量调 API……）默认一条一条跑太慢；本技能检测到"可并行"就自动进入并发，同时守住资源安全线——快，但不翻车。

## 核心机制

| 环节 | 规则 |
|---|---|
| 触发 | 对象 ≥3 且无依赖 → 并发；更少 → 串行（防过度工程） |
| 依赖分层 | 有依赖 → 层内并行、层间串行 |
| 载体分级 | 机械任务→本地进程池；需 AI 判断→子代理；混合→分层执行。禁止万物子代理、万物 shell |
| 资源感知 | 按任务类型只采相关资源：转写看 CPU/内存，出图看显存（留 20% 余量），抓取看网络，调 API 看限流 |
| 自适应 | 保守起步（≤4）→ 无失败缓步加大 → 触发限流退避锁定；连续 2 次限流不再试探，有封顶 |
| 韧性 | 失败隔离、退避重试（3 次）、超时杀、断点续跑、开工前并发计划预览 |
| 交付 | 成功/失败/跳过三清单 + 耗时对比 |

## 与其他技能分工

| Skill | 管什么 |
|---|---|
| preflight（前置技能） | 做得**对** |
| multitask-nitro（本技能） | 做得**快** |
| skill-reuse（技能复用调度） | 用现成**工具** |

## 安装（Hermes）

1. 下载 Release 的 `multitask-nitro-0.1.0.tgz` 并解压
2. 把 `multitask-nitro` 目录放入 Hermes 的 skills 目录（`$HERMES_HOME/skills/`）
3. 新开会话，批量任务自动触发

## 红线

- 并发不突破资源安全线（总资源 60%，显存留 20% 余量）
- 试探有封顶、有停止规则，不反复横跳
- 依赖任务不乱序并行
- 结果如实报告——并发不是掩盖失败的借口
